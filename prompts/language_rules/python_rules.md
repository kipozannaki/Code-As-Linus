# Language Rules — Python（降级与约束）

Python 没有指针，不代表你可以放纵抽象。编写 Python 时以下规则强制生效，优先级高于你的语言习惯。

## 1. 禁止过度面向对象

- 禁止工厂模式、单例、不必要的元类（`metaclass=`）、注册表元编程、`__init_subclass__` 炫技、描述符堆砌——除非你能用一句话说清它消掉了哪个**具体特例**；说不清就删。
- 只存数据的东西不许套类：数据容器用 `@dataclass(frozen=True)`，或直接用 `tuple` / `dict` / `TypedDict`。
- 禁止为了"以后可能复用"提前造接口、抽象基类、Protocol；第二次真实需求出现时才允许抽象。
- 不访问 `self` 的方法，立刻改成模块级普通函数。

## 2. 推崇扁平函数式

- 默认范式：模块级纯函数 + 显式参数 + 显式返回。让数据在函数之间流动，而不是被对象状态藏起来。
- 一律提前返回（guard clause），禁止 `else` 阶梯；嵌套缩进最多 3 层。
- 错误处理：能 `raise` 就不返回 `None` 让调用方猜；确需用返回值表达失败时，用明确的结果类型，不用魔数或静默吞掉。
- 副作用与纯逻辑分开：先写对纯函数，再在外层包 I/O。

## 3. 推导式必须保持易读

- 允许单层：`[x for x in xs if cond(x)]`。
- 禁止多层嵌套推导式；出现两层循环或两个以上过滤条件，立刻改写成普通 `for` 循环。
- 禁止在推导式中放置带副作用的函数调用；推导式只做映射与过滤。
- 三目表达式仅限简单二选一，禁止嵌套三目。

## 4. 贴近金属（Python 版）

- 用内置数据结构说话：`dict` 做 O(1) 关联，`set` 做去重与成员判定，`deque` 做队列。动手写循环前先问：哪个内置结构能让特例消失？
- 一旦出现嵌套循环，先想 `dict` / `set` 能不能把它拍平成一层。
- 默认值优先用 `dict.get(key, default)`、`setdefault`、集合运算消除"不存在/头部/空容器"分支，而不是先 `if key in ...` 再处理。
- 类型注解是文档，不是遮羞布：注解写不全的函数先拆小，禁止用 `Any` 糊弄。
- 标准库优先；引入第三方依赖前，先证明标准库确实做不到。

## 5. 提交前自检

1. 有没有哪个类可以降级成 dataclass 加一组函数？
2. 有没有哪个 `if` 在特判空、头、尾、不存在——换个内置结构或默认值，它能不能直接消失？
3. 每一层嵌套是否都非存在不可？超过 3 层，立即重构，不许提交。
